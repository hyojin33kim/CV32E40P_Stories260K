# I1: int8 weights with per-row scale (fp32 activations and MAC) — 11-21

Conclusion: weight-only int8 (one fp32 scale per output row, integer weights, fp32 accumulation) runs on the GEMV
engine **bit-identical to a new RISC-V software reference and host model**, costs +0.0023 nats/token (argmax
agreement 0.987), cuts weight storage and weight reads to about 1/4, and keeps step cycles equal to the fp32 design
(on-chip) or +4.9 % (weights in DDR, model with 40 cycles latency). Not run on a board; 150 MHz timing of the new
logic is not closed yet (see the end).

## Numeric definition (the new reference; defined by `w8/make_run_w8.py`)
For each output row i of W (d rows, n columns): `m = max|W[i][j]|`, `s = m / 127.0f`, `wq = clamp(rintf(W/s), -127, 127)`
(`s = 0`, `wq = 0` for an all-zero row), `acc = 0.0f; acc += (float)wq[j] * x[j]` in j order (fmul then fadd, no FMA),
`y[i] = acc * s`. `(float)wq` is exact, so the MAC is the same fmul + fadd as the fp32 path and the result is
independent of lanes, FPU latency and memory timing. Applies to the 7 weight matmuls per layer (Wq, Wk, Wv, Wo, W1,
W2, W3) and the classifier; attention QK/AV, KV cache, rmsnorm, RoPE, softmax, SiLU, the embedding lookup stay fp32.
Combined with Option A (the W8 host model is generated from `opta/run_opta.c`).

## Memory
int8 matrices + scales: 0x20000..0x630E0 = 268 KiB (fp32: 1 MiB, 0x20000..0xFD400). Row stride padded to 16 B
(n = 172 -> 176). Embedding table stays fp32 (128 KB, used for the lookup); the classifier uses its int8 copy.

## GEMV mode D (RTL)
A 16 B line = 16 consecutive j of one row; a FIFO word = 4 weights (same FIFO as mode A); a word is popped every 4th
j and, at the row end, together with the pad words (4 x ceil(n/16) - ceil(n/4) of them). int8 -> fp32 conversion is
combinational in front of the existing fmul. Row scales are loaded one 16 B line (4 rows) at a time into a banked
`sbuf` (state `LOADS`, LANES == 4), read one cycle ahead of the fadd result and multiplied once per finished row by
a per-lane fmul; rows are counted finished at that stage. Needs FPU_LAT >= 1, 16 B aligned rows and scales.

## Results (measured)
Accuracy (host, Option A numerics, 4 prompts x 512 steps teacher forced on the fp32 model's tokens): nll_delta
+0.0023 nats/token (per prompt 0.0017, 0.0009, 0.0038, 0.0027), argmax agreement 0.987, logits rel L2 0.0088.
Proposed pass criterion (nll_delta <= 0.01, argmax >= 0.97) is met; the criterion itself is the user's decision.

Bit-exactness: RISC-V `-Os` software W8 vs host W8 (8 steps): logits and KV difference 0. Accelerator (`soc_top`,
`GEN_ACC=full`) vs the software run (8 steps): identical logits, KV and tokens; 64 steps vs the host: 64/64 steps
bit-identical logits, KV difference 0. On-chip board top and DDR board top (image of 8 steps): KV and token regions
identical to the `soc_top` dump (only cycle counters differ).

Cycles (8-token image, Option A full offload):
| | fp32 | int8 (W8) |
|---|---:|---:|
| `soc_top` first step | 147,875 | 146,873 |
| on-chip board top, step 1 / total | 148,262 (ctx 1) / 1,263,796 | 147,399 / 1,255,546 |
| DDR board top (40 cycles latency, 12.8 B/cycle), total | 1,457,596 (+15.3 %) | 1,342,698 (+6.9 %) |
| accelerator memory reads, 8 steps | about 519K lines | 206K lines |
The DDR total includes about 31K cycles (estimate) of one-time CPU word reads at boot. With int8 the DDR run is
latency bound, not bandwidth bound (bandwidth 12.8 vs unlimited: no difference; latency 40 -> 80: +14 % more).

Bug found and fixed during verification: the first LOADS (scales word by word) issued one AXI read per word
(+17K cycles per step), and the external-read flag was off during LOADS (wrong data on the DDR top, caught by the
byte comparison). Scales are now loaded by line and the flag covers LOADS.

## Limits and open items
- Only static weights are int8; the KV cache and activations stay fp32. int8 x int8 integer MAC lanes (I2) need an
  activation quantizer in hardware (a CPU loop would cost about 50K cycles per step, estimate) and are not started.
- Scale loading is not overlapped with the first weight fetch (remaining +7K cycles per step on the DDR top, estimate).
- The per-lane scale fmul adds 4 FPUs; a shared multiplier would save area (not done).
- Synthesis: see `acc/S5B_DDR_AXI.md` / PROGRESS.md for the latest 150 MHz result of the DDR top with mode D.
