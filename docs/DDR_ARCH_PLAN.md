# DDR 중심 구조 계획 (결정 D9, 2026-11-28)

목표(사용자): **DDR 구조를 먼저 만들고, 그 위에서 Stories260K와 Stories15M을 같은 구조로 실행한다.** 칩 안 RAM은 RISC-V(CPU)가 쓰는 최소한만 둔다.
표기: **측정** = 이 저장소에서 명령으로 얻은 값, **계산** = 숫자 계산, **추정**, **미확인**. 15M 모델 파일 `stories15M.bin`은 11-28 14:36에 사용자가 저장소 루트에 받아 두었다(추적되지 않음, 60,816,028 바이트). 헤더를 읽어 구성값을 확인했다: dim 288, hidden 768, 층 6, 헤드 6, KV 헤드 6, vocab 32,000, seq 256. 공개된 해시와의 대조와 토크나이저는 아직 없다.

## 1. 지금 있는 것 (사실)
- `acc/axi_ext_rd.sv` + `acc/chip_axi_ddr_top.sv`: **가중치만** DDR에서 읽는 읽기 전용 AXI4 마스터(128비트, 버스트, 요청 크레딧). 260K에서 비트 일치, 토큰당 +49,943사이클(ctx 1 +31.7 %, ctx 512 +13.0 %, DDR 모델 지연 40, 12.8 B/사이클, 측정, `acc/S5B_DDR_AXI.md`).
- `gemv_acc`는 명령마다 `W_ADDR < EXT_BELOW`이면 그 명령의 가중치 읽기를 외부(DDR)로 보낸다. 즉 **KV를 같은 외부 창 안에 두면 어텐션 읽기는 구조 변경 없이 DDR로 간다**(코드 확인).
- 쓰기 경로는 없다. 외부 창 주소에 CPU가 쓰면 무시된다. CPU의 외부 읽기는 워드당 약 41사이클(측정 모델 값)이고 CPU에 데이터 캐시는 없다.
- 시뮬레이터 `sim_axi_ddr.cpp`는 row/bank DRAM 타이밍(tRCD, tRP, tFAW, 리프레시 등)을 가진 **읽기 전용** 모델이다.

## 2. 설계

### 2.1 데이터 배치
| 데이터 | 260K 크기 | 15M 크기(계산) | 접근 | 위치 |
|---|---|---|---|---|
| 가중치 | fp32 약 1 MiB / int8 약 0.25 MiB | int8 14.69 MiB (fp32 57.94 MiB) | 토큰당 1회 순차 읽기 | DDR (구현됨) |
| KV 캐시 | 0.625 MiB | fp32 3.375 MiB, int8 0.914 MiB | 읽기 순차, 쓰기는 토큰당 층마다 작은 행 | DDR (쓰기 경로 신규) |
| 활성값, 어텐션 점수, 로짓 | 약 21 KiB | 로짓 125 KiB 포함 약 140 KiB(분할 argmax면 줄일 수 있음) | CPU와 가속기의 무작위 접근 | 칩 안 RAM |
| 스택, .bss, RMS 가중치 복사 | 수 KiB | 수 KiB | CPU 전용 | 칩 안 RAM |
| 코드 | 7.6 KB | 비슷하거나 약간 큼(추정) | CPU 인출 | imem BRAM 16 KiB |

칩 안 데이터 RAM 크기: **260K는 최소 약 32 KiB, 여유 64 KiB**, **15M은 약 256 KiB**(로짓 125 KiB가 지배. 분류기를 1,024행씩 나눠 argmax를 조각별로 갱신하면 줄일 수 있으나 새 펌웨어 로직이므로 미정). 크기는 모델별 파라미터로 둔다.

### 2.2 KV 레이아웃은 head-major로 (이 설계의 핵심)
지금 KV는 `[층][시간 t][kv_dim]` 순서이고 헤드의 조각이 시간마다 `kv_dim*4` 바이트 간격으로 흩어져 있다(`gen/firmware_gen.c`의 `acc_gemv` 호출 인자).
- QK(모드 A): 행 하나가 head_size개 float(260K는 8개 = 32 B = 2줄, 15M은 48개 = 192 B = 12줄)이고 행 간격이 `kv_dim*4`라서 **작은 조각이 흩어져** 읽힌다.
- AV(모드 B): 시간마다 16 B 한 줄씩이고 간격이 `kv_dim*4`다. 버스트로 합쳐지지 않는다.
- SRAM에서는 문제가 없지만 DDR에서는 요청 하나가 16~32 B라 버스트 효율이 나쁘다(DDR4의 최소 접근 단위는 64 B로 알려져 있어 낭비가 커질 것으로 추정, 미측정).

해결: **헤드마다 연속** 배치 `[층][kv헤드][시간 t][head_size]`.
- QK: `W_STRIDE = head_size*4`, 행이 연속이라 한 헤드의 모든 시간이 하나의 스트림(버스트 최대 16줄).
- AV(모드 B): `J_STRIDE = head_size*4`가 16의 배수(260K 32 B, 15M 192 B, 둘 다 조건 충족)이고 줄이 연속.
- 쓰기: 토큰마다 헤드당 K 한 행과 V 한 행이 각각 head_size*4 바이트(260K 32 B, 15M 192 B)의 연속 쓰기가 된다.
`gemv_acc` RTL은 바꾸지 않고 펌웨어의 주소와 stride 인자만 바꾼다(코드를 읽고 한 판단이며 시뮬레이션 전).

### 2.3 쓰기 경로: `axi_ext_wr` (신규, 작게)
- CPU의 외부 창 쓰기를 작은 쓰기 결합 버퍼(예: 한 헤드 행 = 32 B 또는 192 B)에 모아 **AXI 쓰기 버스트 한 번**으로 DDR에 쓴다. 일반 DMA는 만들지 않는다.
- **순서 보장은 하드웨어 인터락으로**: 미완료 쓰기(AXI B 응답을 받지 못한 것)가 있으면 `gemv_acc`와 `vfu`의 시작을 지연하고, CPU의 외부 읽기도 기다리게 한다. 소프트웨어가 `fence`를 기억해야 하는 구조는 조용히 틀릴 위험이 커서 쓰지 않는다.
- 쓰기 응답 오류는 기존 읽기와 같은 방식(sticky err 비트)으로 올린다.

### 2.4 주소 맵과 펌웨어
- 외부 창은 가중치와 KV를 모두 포함(`EXT_BELOW`가 둘 위에 있음). SRAM 기준주소, imem, 스택은 모델별 파라미터.
- `firmware_gen.c`의 절대 주소(0x1a0000 등), `link.ld`, `image.py`, 이미지 적재는 **레이아웃 파일에서 생성**하도록 바꾼다(PLAYBOOK 게이트 15-3과 같은 작업).
- int8 가중치는 이미 지원(모드 D)한다. 15M은 int8이 필수(D1 합격 기준 미결정, 임시로 제안값 사용).

## 4. 위험과 권고가 뒤집히는 조건
- KV head-major의 이득은 P0에서 시뮬레이션으로 확인했다(E18: -31.7 %, 칩 안 대비 +8.5 %). DDR 모델 가정(지연 40, 12.8 B/사이클) 안에서의 값이고 보드 DDR은 미확인이다. 읽는 양은 KV 크기의 2배(질의 헤드 2개가 KV 헤드 하나를 따로 읽음)로 앞의 "상한 약 51K사이클" 계산은 절반으로 잘못 잡은 값이다.
- **보드 DDR 지연이 80사이클 이상**이면 이미 측정된 대로 +26 % 이상이 붙는다. 그때는 크레딧(CRED)과 FIFO 증설을 함께 본다.
- **15M의 병목은 SRAM 포트 B 사용률(60~74 %)과 DDR 대역폭**이라 NPU를 늘려도 이득이 제한적이다(E15).
- 쓰기 마스터와 인터락의 순서 오류는 비트 일치 시험이 놓칠 수 있는 종류의 결함이라, P1에서 변조 시험(인터락을 끄면 실패하는지)을 반드시 한다.
- 이 구조는 260K의 속도에 불리하다(칩 안 구성이 더 빠름). 목적이 15M 준비일 때만 가치가 있다.
